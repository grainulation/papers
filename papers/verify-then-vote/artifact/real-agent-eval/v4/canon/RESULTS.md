## Caveats

- Canonicalization is applied to OBJECTS only. Subjects are untouched, so sets split by subject wording ("glass" vs "no, glass", "this", "it") stay split; no new conflict sets can appear.
- Graders see the raw object. Where a canonical class merges strings the lexical graders score differently (see the merge table), majority's correctness depends on which raw member it returns (the first member of the winning class, as before).
- The rules are conservative by design (tests in `test_canon.py`), so many paraphrases stay distinct; the result bounds what *formatting-only* canonicalization can do, not semantic clustering.
- Same small-sample caveats as v3: every McNemar p and bootstrap CI here is underpowered.
